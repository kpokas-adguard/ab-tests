# Сценарии QA для A/B-теста

Передаётся QA на шаге 6. Подставь `experiment_name` и `version_name` своего теста.

## Smoke (обязательный минимум)

1. Opt-in → `/api/v1/session_start` уходит, варианты применяются
2. Повторный запуск → `tests` не уходит, варианты те же
3. В одном ключевом событии → `experiment_1/2` корректны
4. Таймаут `/session_start` → дефолт, без `experiment_*`, без краша
5. Обновление со сменой слотов → сброс и переназначение
6. Старт с telemetry off, затем включение → `/session_start` уходит в момент включения,
   варианты применяются без ожидания следующего старта приложения

---

## 1. Opt-in / Opt-out

- [ ] Телеметрия включена на старте → запрос при старте, вариант применён и закреплён
- [ ] Телеметрия выключена на старте, включена позже → запрос в момент включения
- [ ] Телеметрия так и не включена → запрос не отправляется, `experiment_*` отсутствуют, локальный дефолт

## 2. Контракт /session_start

- [ ] Первый старт / после очистки данных → `tests` есть, versions приходит
- [ ] Повторный старт → `tests` отсутствует для закреплённых, варианты те же
- [ ] Частичный ответ → `tests` уходит только для невыбранных экспериментов
- [ ] Отправляется не более одного раза за жизнь процесса

## 3. Применение вариантов

- [ ] `a_def` → дефолтное поведение
- [ ] `b` / `c` → поведение по ТЗ (UI + логика)
- [ ] После закрепления `tests` больше не отправляется

## 4. Свойства в Plausible

- [ ] В ключевых событиях есть `experiment_1/2`, значения равны `version_name` без преобразований
- [ ] Нет пустых `experiment_3` и т.п.
- [ ] При дефолте/ошибке `experiment_*` не отправляются
- [ ] До получения assignment события либо не отправляются, либо сохраняются и уходят позже
      (консистентно для платформы)

## 5. Негативные сценарии

- [ ] Пустой ответ → дефолт, без закрепления, `tests` повторяется на следующем старте
- [ ] Таймаут / ошибка сети → дефолт, без краша, повтор на следующем старте
- [ ] Некорректный ответ → дефолт для проблемных экспериментов, без падений
- [ ] **Неизвестный `version_name`** → локальный дефолт, значение НЕ закрепляется,
      `experiment_*` не отправляется

## 6. Обновление приложения

- [ ] Без изменения маппинга → закрепление сохраняется
- [ ] Со сменой маппинга/слотов → локальные значения очищаются, `tests` уходит заново

---

## Что прикладывать к баг-репорту

1. Версия приложения, платформа, билд
2. Состояние телеметрии: opt-in / opt-out
3. Логи `/session_start` (request/response)
4. Доказательство применения варианта (скрин/лог)
5. Пример события Plausible (payload/лог)
6. Шаги воспроизведения + ожидаемое / фактическое
