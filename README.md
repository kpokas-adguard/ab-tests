# A/B-тесты AdGuard — помощник для продакт-менеджера

Это папка с ИИ-агентом для VS Code. Агент помогает вести A/B-тесты:
готовит карточку теста, проверяет, всё ли в порядке с идущим тестом,
показывает дашборд и находит расхождения между Jira, Notion и продом.

Пишешь ему по-человечески — «проверь AG-58893», «покажи дашборд» —
он сам понимает, что делать.

## Что такое A/B-тест здесь, в двух словах

Продукт (AdGuard для Windows, Android, расширение, VPN…) показывает части
пользователей разные варианты экрана и смотрит, какой работает лучше.
У каждой платформы есть три «слота» — `experiment_1`, `experiment_2`,
`experiment_3` — каналы, по которым приходят данные. Слотов мало, поэтому
главное правило: **новый тест запускают только на чистый слот** — старый
тест на нём закрыт на бэке и убран из кода. Иначе результату нельзя верить.

Один тест — это семь задач в Jira (продуктовая, дизайн, регистрация на
бэке, разработка, удаление из кода, закрытие на бэке, макеты) и одна
карточка в Notion. Агент помогает всё это не потерять.

## Что умеет агент

| Ты говоришь | Что происходит |
| ----------- | -------------- |
| «хочу протестировать X на Android» | ведёт по шагам к готовой карточке теста: изучает данные, задаёт вопросы, предлагает имя, создаёт продуктовую задачу и карточку в Notion |
| «проверь AG-58893» | разбирает один тест: что в Jira, что в проде, чего не хватает, что исправить |
| «покажи дашборд» | собирает страницу с картиной по всем тестам и открывает в браузере |
| «где расхождения» | сверяет задачи, карточки и прод по всем тестам, показывает несостыковки |
| «обнови из Jira» | подтягивает свежие данные по тестам |
| «что пробовали с онбордингом?» | карта задач Jira по теме за три года: что меняли, что было тестом — без чтения задач |

Не знаешь, что спросить — напиши `/ab`, покажет меню из этих шести пунктов.

### Что агент делает и чего не делает

- **Jira и Notion — только читает.** Единственное исключение — при подготовке
  карточки он может создать продуктовую задачу и карточку в Notion.
- **Перед любым созданием спрашивает** — «Мне создать задачу?» — и ждёт «да».
- **Ничего не выдумывает.** Не нашёл данные — говорит «не нашёл».
- **Видит только твои продукты.** VPN-продакт не видит тесты блокировщика
  и наоборот. Исключение — библиотека имён: имена тестов уникальны на всю
  компанию, поэтому там все.
- Попросишь изменить что-то в Jira — ответит «Ничего не могу сделать».

## Установка — три шага

Нужно: VS Code с Copilot и TokenGuard по гайду компании, доступ к Jira и
Notion через MCP (aiguard). Если чего-то нет — агент-установщик скажет.

**1. Скачай папку** в домашний каталог — путь именно такой:

```bash
git clone https://github.com/kpokas-adguard/ab-tests.git ~/ab-tests
```

Открой её в VS Code: File → Open Folder → `ab-tests`.

**2. Запусти установщика.** В чате Copilot нажми переключатель у поля ввода
(там, где Agent / Ask / Plan), выбери **Setup**, напиши «начинай».

Он проверит, что настроено, и поведёт по шагам — по одному. Спросит, кто ты
и с каким продуктом работаешь (VPN, AdBlocker или все). Токены и вход
в Notion попросит сделать тебя — чужие пароли он не вводит. В конце
предложит заполнить базу тестов из Jira и откроет дашборд.

**3. Работай.** В том же переключателе выбери **A/B Tests** и пиши
по-человечески.

Подробнее — `ONBOARDING.md`. Проверить, всё ли настроено, можно
и без агента:

```bash
~/ab-tests/bin/ab doctor
```

## Дашборд

`dashboard.html` — одна страница: слоты по живым данным, активные тесты,
что не так по каждому, архив, библиотека имён, примеры задач. Открывается
через агента («покажи дашборд») или командой:

```bash
~/ab-tests/bin/ab-dash
```

## Что где лежит

| Файл или папка | Что это |
| -------------- | ------- |
| `.github/agents/` | два агента: **Setup** (установка) и **A/B Tests** (работа) |
| `.github/prompts/` | команды `/ab`, `/research-card`, `/ab-check`, `/ab-diff`, `/ab-sync`, `/ab-history` |
| `bin/` | программы: `ab` (трекер), `ab-dash` (дашборд), `ab-plausible` (прод), `ab-pack` (архив для передачи) |
| `tests/` | карточки тестов, одна на тест — заполняются из Jira, в git не идут |
| `templates/` | шаблоны семи задач Jira и карточки Notion, с заполненными примерами |
| `config.yml` | общие настройки: продукты, платформы, слоты, площадки |
| `config.local.yml` | личное: кто ты, твои продукты — создаёт Setup, в git не идёт |
| `CONTEXT.md` | как всё устроено — первое, что читает агент |
| `RESEARCH-CARD.md` | пошаговый сценарий подготовки карточки |
| `HISTORY.md`, `TOPICS.md`, `history/` | «что пробовали»: сценарий, словарь слов по темам, накопленные карты |
| `AGENT-BRIEF.md` | правила агента и сценарий проверки теста |
| `RULES.md`, `PROCESS.md`, `NAMING.md` | правила тестов, процесс по фазам, как называть тесты |
| `FACTS.md` | справочник Jira и Notion — агент ведёт сам |
| `KNOWN-CORRECTIONS.md` | твои поправки агенту, если он ошибается |
| `proposal/` | предложение команде по автоматизации процесса |

## Для тех, кто любит терминал

```bash
ab board            # слоты, тесты по стадиям, что не хватает
ab check AG-58893   # что не закрыто на текущей стадии
ab info AG-58893    # всё о тесте в десять строк
ab fix              # что не закрыто и какой командой чинится
ab week             # сводка на неделю
ab doctor           # проверка окружения
```

Чтобы писать `ab` вместо полного пути: `alias ab="~/ab-tests/bin/ab"` в `~/.zshrc`.

## Если что-то не так

- агент не видит Jira → MCP-роутер не запущен: `MCP: List Servers` в VS Code
- 403 от Plausible → включи корпоративный VPN
- агент ошибается в одном и том же → запиши в `KNOWN-CORRECTIONS.md`,
  он читает его раньше остальных правил
- агент предлагает изменить задачу в Jira → так быть не должно, запиши туда же

## Для ИИ-агента, читающего это вне VS Code

Точка входа — `CONTEXT.md`: модель данных, кто какие поля пишет, правила
подтверждения, быстрые команды. Сценарии — по ссылкам оттуда. Jira и Notion
только чтение, кроме двух режимов, описанных в `RESEARCH-CARD.md`
и `CREATE-TASKS.md`. Ничего не создавай и не меняй снаружи без вопроса
в формате из `CONTEXT.md` и ответа «да».
