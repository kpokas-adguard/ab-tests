# Трекер A/B-тестов

Один тест = одна платформа = один файл в `tests/`.

## Как команды работают вместе

Четыре команды — один сервис. Не конфликтуют, потому что у каждого поля
карточки один владелец, и CLI это проверяет:

| Владелец | Поля | Кто пишет |
| -------- | ---- | --------- |
| pm | гипотеза, метрики, ветки, слот, имя | человек, `/research-card` |
| jira | стадия, задачи, версии, закрытие | `/ab-sync`, `/ab-check` |

`ab set <ключ> --as jira hypothesis=…` → отказ. Список — `config.yml`,
секция `field_owners`.

Общий вход для всех — `CONTEXT.md`, 105 строк. Детальные файлы
читаются по ссылкам, когда нужны, а не при старте.

```
bin/ab info <id>                       всё о тесте одной командой
bin/ab set <id> --as <роль> п=з п=з    запись с проверкой владельца
bin/ab fact get|set <секция>           FACTS.md по секциям, не целиком
```

## Как пользоваться

**Агент «A/B Tests»** — выбери в переключателе рядом с Agent / Ask / Plan, в списке с Coder и Planner,
и пиши по-человечески: «проверь AG-58893», «покажи дашборд», «хочу
протестировать X». Слэши не нужны.

**Или `/ab`** — одна команда, покажет меню из пяти пунктов.

Отдельные команды остались для тех, кто привык:

| Команда | Что делает |
| ------- | ---------- |
| `/research-card` | карточка от продуктовой задачи до проверки перед передачей |
| `/ab-check` | один тест: разбор, сверка с продом, дозаполнение |
| `/ab-diff` | расхождения Jira ↔ Notion ↔ прод по всем тестам |
| `/ab-sync` | подтянуть все тесты из Jira в трекер |

Новому продакту — `ONBOARDING.md`.

Убранные команды — в `archive/prompts/`.

## Команды в терминале

```
bin/ab board      # слоты, стадии, дедлайны
bin/ab slots      # гигиена слотов: где хвост портит следующий тест
bin/ab week       # недельная сводка
bin/ab check <id> # что не закрыто на текущей стадии
bin/ab new <id> <платформа>
```

Удобнее — в `~/.zshrc`: `alias ab="~/ab-tests/bin/ab"`

## Точечные исправления

```
bin/ab fix              что не закрыто и какой командой чинится
bin/ab fix <id>         то же для одного теста
bin/ab set <id> <поле> <значение>
```

Примеры:
```
bin/ab set AG-57632 tasks.cleanup AG-57633
bin/ab set AG-57632 backend_finished_at today
bin/ab set AG-51010 code_removed_version 5.6
```

Значения `today`, `true`, `false`, `null` понимаются как даты и флаги.

Не знаешь значение — `/ab-recheck <ключ>` в чате: агент найдёт в Jira
и запишет сам, не перелопачивая всю базу.

## Дашборд

```
bin/ab-dash            собрать HTML и открыть в браузере
bin/ab-dash --no-open  только собрать
```

Файл `dashboard.html` — слоты по живым данным Plausible, активные тесты,
дедлайны и ссылки на задачи. Можно показывать команде и руководству.

Данные о тестах берутся из `tests/*.md`. Чтобы подтянуть их из Jira,
скажи в чате `/ab-sync`.

## Данные из Plausible — `bin/ab-plausible`

```
bin/ab-plausible check                    проверить доступ к API
bin/ab-plausible slot <id>                кто шлёт в слот — детект загрязнения
bin/ab-plausible goal <id> <событие>      конверсия по вариантам
```

Перед первым запуском заполни в `config.yml` секцию `plausible` (base_url и site_ids)
и положи токен: `echo 'ТОКЕН' > ~/.plausible-key && chmod 600 ~/.plausible-key`

## Шаблоны Jira — `templates/`

Текст для копипаста руками. Ничего никуда не отправляется.

| Файл | Когда |
|---|---|
| `jira-backend-task.md` | первой — отсюда берётся `experiment_name` |
| `jira-design-task.md` | дизайн блокирует разработку |
| `jira-dev-task.md` | **новый** — у разработки шаблона не было |
| `jira-cleanup-task.md` | вместе с dev-задачей, не после результата |
| `jira-backend-close-task.md` | после решения — закрытие на бэке |
| `examples/` | семь заполненных примеров в порядке цикла |
| `research-card.md` | карточка Research Board |

## Документы

- `PROCESS.md` — чеклист по шагам 0–10 с гейтами
- `QA-CHECKLIST.md` — сценарии для QA
- `TEMPLATE.md` — поля карточки теста
- `config.yml` — платформы, слоты, пороги

## Для ИИ-агента с доступом к Jira и Notion

- `AGENT-BRIEF.md` — что агент должен уметь, какие поля тянуть, режим read-only
- `KNOWN-CORRECTIONS.md` — поправки, которые ты вносишь после обкатки

Агент работает только на чтение. На любую просьбу что-то изменить
он обязан отвечать «Ничего не могу сделать».

## Главное правило

Слот `experiment_N` чист только когда предыдущий тест на нём
**помечен finished на бэке И удалён из кода клиента в вышедшей версии.**
Запуск на грязный слот даёт результат, которому нельзя верить.
