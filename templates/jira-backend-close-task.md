# Шаблон бэк-задачи на закрытие теста

По образцу ADG-12170. Заводится, когда решение по тесту принято.
**Это не выпиливание из кода** — это остановка эксперимента на бэке.
Обе задачи нужны, они закрывают разные вещи.

# Описание

## Проблема

Тест `<AG-XXXXX>` завершён, но не закрыт в сервисе A/B-тестирования,
из-за чего пользователи продолжают распределяться по веткам и нет финальной
фиксации победившего варианта.

## Вводные данные

**Название теста в сервисе:** `<AG-XXXXX-slug>`

**Версии, участвующие в тесте:**
- `-a_def` — `<что было>` (контроль)
- `-b` — `<что тестировали>` (вариант теста)

**Победил:** `<-b — описание>` / `<-a_def — эффекта нет, оставляем контроль>`

## Tech solution

1. Перевести эксперимент `<AG-XXXXX-slug>` в статус `closed` в A/B-сервисе
2. Назначить победившую ветку `<-b>` как fallback (100% трафика)
3. Остановить дальнейшее рандомное распределение по вариантам теста

## Definition of Done

- [ ] Тест `<AG-XXXXX>` закрыт в сервисе A/B-тестирования
- [ ] Победившая ветка выставлена как fallback для всех пользователей
- [ ] Рандомизация по `-a_def` / `-b` остановлена
- [ ] Изменение отражено в конфиге и готово к клиентскому релизному циклу

## Связи

| Тип | Задача |
|---|---|
| Relates to | `<AG-XXXXX>` — dev-задача теста |
| Relates to | `<AG-XXXXX>` — задача на выпиливание из клиента |

---

## Почему одной задачи недостаточно

Закрытие на бэке останавливает **распределение новых пользователей**.
Но у тех, кто уже получил вариант, он закреплён локально, и клиент продолжает
слать `experiment_*` до тех пор, пока эксперимент не удалён из кода приложения.

Поэтому слот считается чистым только когда закрыты обе задачи:
эта и выпиливание из клиента.
