# Подключение — для нового продакта

Полчаса, если VS Code с Copilot и TokenGuard уже настроен по гайду компании.

## Что это

Папка, в которой агент в VS Code ведёт A/B-тесты: готовит карточки в Notion,
проверяет тесты в Jira и проде, показывает дашборд, находит расхождения.
Один режим чата, пять сценариев, слэши помнить не нужно.

## Как подключиться — три шага

**1. Папка.** Попроси доступ к <https://github.com/kpokas-adguard/ab-tests>
и склонируй в домашнюю папку — путь именно такой, команды на него рассчитывают:

```bash
git clone https://github.com/kpokas-adguard/ab-tests.git ~/ab-tests
```

Открой в VS Code: File → Open Folder → `ab-tests`.
Правки в правилах и промптах можно делать прямо на GitHub — потом `git pull`.

**2. Агент Setup.** В чате нажми переключатель рядом с полем ввода
(там, где Agent / Ask / Plan), выбери **Setup** и напиши «начинай».

Он проверит окружение сам — что есть, чего нет — и поведёт по шагам,
по одному. Токены Jira, Bitbucket, Plausible и вход в Notion — это
попросит сделать тебя: чужие токены агент не вводит. Скажет, где взять.

В конце спросит, кто ты и с каким продуктом работаешь — VPN, AdBlocker
или все, — и выдаст сводку: доступы, проекты, компоненты, что не хватает.

**3. Работа.** Переключись на агента **A/B Tests** и пиши по-человечески:
«покажи дашборд», «проверь AG-58893», «хочу протестировать X».

Проверить окружение можно и без агента:

```bash
~/ab-tests/bin/ab doctor
```

## Что где лежит — если понадобится

| Файл | Что |
| ---- | --- |
| `CONTEXT.md` | как всё устроено — единственное, что агент читает при старте |
| `dashboard.html` | дашборд, пересобирается `bin/ab-dash` |
| `tests/*.md` | карточки тестов, одна на тест — заполняет `/ab-sync`, в git не идут |
| `FACTS.md` | справочник Jira и Notion, агент ведёт сам |
| `KNOWN-CORRECTIONS.md` | твои поправки агенту — пиши сюда, если он ошибается |
| `RULES.md` | обязательные правила, коротко |

## Если что-то не так

- агент не видит Jira → роутер не запущен, `MCP: List Servers` в VS Code
- 403 от Plausible → VPN
- агент ошибается в одном и том же → запиши в `KNOWN-CORRECTIONS.md`,
  он читает его раньше остальных правил
- агент предлагает изменить задачу в Jira → он не должен, это нарушение;
  напиши в `KNOWN-CORRECTIONS.md`

## Важно при передаче

Тесты общие на всю компанию, слоты общие, имена уникальны глобально.
Если папку копируют несколько продактов — данные в `tests/` разойдутся.
В git — только сам инструмент: агенты, правила, шаблоны, общий `config.yml`.
Данные (`tests/`, `NAMES-REGISTRY.md`) и личное (`config.local.yml`, токен)
у каждого свои, заполняются Setup-агентом из Jira и в git не попадают.
