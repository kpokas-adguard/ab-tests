# Правила именования эксперимента и веток

Единый источник. На этот файл ссылаются `RESEARCH-CARD.md` и `CREATE-TASKS.md`.

## experiment_name

```
<ключ dev-задачи>-<slug>
```

Примеры из работающих тестов:

```
AG-57632-home-screen-protection-level
AG-52740-rule-limits
AG-53163-paywall
AG-51019-advanced-settings
AG-52622-general-settings-promo
```

**Ключ** — продуктовой задачи «Проработать A/B-тест». Она создаётся первой,
на шаге 0 подготовки, поэтому ключ известен ещё до карточки. Он же становится
префиксом названия карточки в Notion.

Имя фиксируется **в карточке**, и все задачи — дизайн, бэк, разработка —
берут его оттуда дословно. Не наоборот.

В старых тестах ключ брали из dev-задачи (AG-57632) или дизайн-задачи
(AG-52740) — единообразия не было. С этого момента — только продуктовая.

**slug** — что меняем, а не зачем:

- английский, нижний регистр, слова через дефис
- от одного до четырёх слов
- называй объект изменения: экран, блок, механику
- без номеров версий, дат, имён людей, слова `test` и `ab`

Хорошо: `rule-limits`, `home-screen-protection-level`, `general-settings-promo`
Плохо: `new-onboarding-v2`, `ksenia-test`, `ab-paywall-2026`

## Уникальность — обязательная проверка по ВСЕМ продуктам

Бэк не сможет обработать тест, если `experiment_name` уже был. Сервис
A/B-тестирования один на все продукты — блокировщик и VPN регистрируются
в нём одинаково. Поэтому имя должно быть уникальным **среди всех тестов
компании**, а не только среди тестов блокировщика.

**Это единственное место, где правило «VPN не трогать» не действует.**
Для проверки имени VPN-тесты нужно видеть.

Три источника, все обязательны:

1. **Бэк-задачи в Jira — без фильтра по продукту:**

   ```text
   project = ADG AND text ~ "experiment_name" ORDER BY created DESC
   ```

   Собери все значения `experiment_name` из описаний. Это полный список:
   каждый тест любого продукта регистрируется здесь.

2. **Реестр имён** `NAMES-REGISTRY.md` — локальный кэш всех имён из ADG,
   включая VPN. Обновляется при `/ab-sync`. Быстрая проверка без Jira,
   но может отставать — поэтому пункт 1 обязателен.

3. **Прод:** `~/ab-tests/bin/ab-plausible slots <платформа>` — имена
   в слотах блокировщика. VPN-площадки здесь не видны, для них — пункт 1.

Совпал **slug** с любым прошлым тестом любого продукта — предложи другой.
Ключ в префиксе даёт формальную уникальность, но два теста с одинаковым
slug в отчётах и логах не отличить.

Покажи PM результат проверки, а не только вывод: «искал `onboarding-paid`
в ADG (N задач), реестре и Plausible — совпадений нет».

## Ветки (version_name)

```
<experiment_name>-a_def    контроль, текущее поведение без изменений
<experiment_name>-b        первый тестовый вариант
<experiment_name>-c        второй тестовый вариант, если он есть
```

Суффикс `a_def` у контроля обязателен — по нему на бэке и в Plausible
отличают дефолтную ветку. Не сокращай до `-a`.

Пример полного набора:

```
experiment_name:  AG-57632-home-screen-protection-level
control:          AG-57632-home-screen-protection-level-a_def
вариант B:        AG-57632-home-screen-protection-level-b
```

## Слот

`experiment_1`, `experiment_2` или `experiment_3` — свободный и чистый
на этой платформе. Проверяется командой:

```
~/ab-tests/bin/ab-plausible slots <платформа>
```

Слот фиксируется один раз и не меняется в ходе теста: смена маппинга заставляет
клиенты сбросить закреплённые варианты и обнуляет набранную выборку.

## Где это должно быть записано

Одни и те же значения в трёх местах, дословно совпадающие:

| Где | Что |
|---|---|
| Карточка Notion | `experiment_name`, слот, названия обеих веток |
| Dev-задача Jira | блок «Параметры эксперимента» |
| Бэк-задача Jira (регистрация) | `experiment_name` и список версий |
| Бэк-задача Jira (закрытие) | то же имя + победившая ветка |

Расхождение хотя бы в одном символе означает, что тест не посчитается.
Источник истины — бэк-задача: именно её значение уходит в сервис сплит-тестирования.
