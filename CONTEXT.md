# Продуктовая работа с A/B-тестами — единый контекст

**Читай этот файл первым и, для старта, только его.** Остальные — по ссылкам,
когда дойдёшь до соответствующего шага. Здесь всё, что нужно любой команде,
чтобы начать и не сломать работу другой.

## Четыре команды — один сервис

| Команда | Фаза | Читает | Пишет |
| ------- | ---- | ------ | ----- |
| `/research-card` | подготовка | Plausible, Jira, Notion | Jira (2 задачи), Notion (карточка), `tests/<ключ>.md` — поля **pm** |
| `/ab-check` | любая, один тест | Jira, Notion, Plausible, `tests/` | `tests/<ключ>.md` — поля **jira** |
| `/ab-sync` | все тесты | Jira | `tests/*.md` — поля **jira**; `NAMES-REGISTRY.md` целиком |
| `/ab-diff` | все тесты | всё | ничего — только отчёт |

Они не конфликтуют, потому что **у каждого поля один владелец**, и CLI
это проверяет.

## Модель данных — три владельца полей

Карточка теста — `tests/<ключ>.md`. Каждое поле принадлежит одной роли,
список — в `config.yml`, секция `field_owners`:

| Владелец | Что | Кто пишет |
| -------- | --- | --------- |
| **pm** | гипотеза, метрики, baseline, выборка, ветки, слот, `experiment_name`, `research_card`, `notes` | человек или `/research-card` |
| **jira** | стадия, задачи, версии, даты решений, статусы закрытия | `/ab-sync`, `/ab-check` — только из Jira |
| **meta** | `id`, `platform`, `synced_at`, `checked_at` | система |

**Правило записи:** `ab set <ключ> --as jira поле=значение`. CLI откажет,
если поле не твоё. Без `--as` — запись от имени человека, разрешено всё.
Метка времени `synced_at` / `checked_at` ставится сама.

## Файлы — кто пишет, как

| Файл | Что | Писатель | Как |
| ---- | --- | -------- | --- |
| `tests/<ключ>.md` | один тест | все, по своим полям | `ab set --as <роль>` |
| `NAMES-REGISTRY.md` | все имена, все продукты | только `/ab-sync` | перезапись таблицы целиком |
| `FACTS.md` | окружение: Jira, Notion, схемы | любой | **только** `ab fact set <секция> <текст>` — никогда файл целиком |
| `KNOWN-CORRECTIONS.md` | поправки | только человек | — |
| `config.yml` | платформы, слоты, владение, общее для всех; **кто PM** и продукты — в `config.local.yml` (не в git) | только человек | — |

**В `FACTS.md` — только окружение.** Факты о конкретном тесте, состояние
слотов на дату — нет: это `tests/<ключ>.md` и `ab-plausible`.

## Быстрые команды — вместо чтения файлов

```
ab info <ключ>                     всё о тесте, 10 строк
ab fix <ключ>                      что не закрыто + команда для каждого
ab set <ключ> --as jira п=з п=з    записать несколько полей разом
ab fact get <секция>               одна секция FACTS, не весь файл
ab-plausible slot <ключ>           прод по одной платформе
ab-plausible slots <платформа>     три слота платформы
ab-dash --no-open                  пересобрать дашборд
```

Все — `~/ab-tests/bin/`. Одна команда вместо чтения 500 строк.

## Скорость — три правила

1. **Jira: только нужные поля.** summary, status, components, fixVersions,
   issuelinks, description. Комментарии — только у dev-задачи, только
   ради `experiment_name` и слота. JSON целиком не сохранять и не перечитывать.
2. **Схемы и метаданные — из `FACTS.md`.** Если инструмент или проект
   там есть — не вызывать `Get Tool Schema` и `jira_get_create_meta`.
   Нет — вызвать один раз и записать через `ab fact set`.
3. **Plausible — одна платформа**, если команда про один тест.

## Свежесть — как понять, что данные устарели

- `ab info` показывает `synced_at` и `checked_at`. Старше 7 дней — стоит
  обновить, но **сначала спроси**, не перечитывай всё молча.
- Дашборд показывает возраст данных в шапке.
- Прод (Plausible) всегда свежий — тянется при каждой сборке дашборда.
- Порядок доверия при конфликте: **прод → Jira → Notion → трекер**.
  Прод пуст, трекер говорит «занят» — это «запланирован», не противоречие.

## Подтверждение перед любым действием наружу

Всё, что создаёт или меняет что-то за пределами чтения, — **только после
явного «да»**. Не «покажу и сделаю», а «покажу, спрошу, остановлюсь».

**Что требует подтверждения:**

| Действие | Вопрос |
| -------- | ------ |
| создать задачу в Jira | «Мне создать задачу?» + черновик |
| создать несколько задач | «Мне создать эти N задач?» + список |
| создать страницу в Notion | «Мне создать карточку?» + черновик |
| изменить страницу в Notion | «Мне изменить карточку?» + что именно |
| дописать в существующую задачу Jira | «Мне дописать в задачу X?» + текст |
| создать локальную карточку `ab new` | «Мне завести карточку X?» |
| заменить уже заполненное поле | «Мне заменить поле: было … → станет …?» |
| записать в `config.yml` | «Мне записать в настройки: …?» |
| записать в `FACTS.md` | «Мне записать в справочник: …?» |

**Что НЕ требует:** чтение чего угодно, дозаполнение пустых полей через
`ab set`, пересборка дашборда, метки `synced_at` / `checked_at`.

**Формат — всегда один, чтобы глаз привык:**

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Мне <действие>?

Где:   Jira · проект AG
Что:   <черновик или список, коротко>

→ да / нет / поправить
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

После вопроса — **стоп**. Ничего не делай, пока не пришло «да». «Поправить» —
покажи новый черновик и спроси снова. «Нет» — не делай и не переспрашивай.

Несколько действий подряд — несколько вопросов, по одному. Не объединяй
«создать задачу» и «изменить карточку» в один вопрос: человек может хотеть
одно, но не другое.

## Железные правила — для всех команд

- **Jira и Notion — только чтение**, кроме двух режимов: `RESEARCH-CARD.md`
  (две продуктовые задачи + карточка) и `CREATE-TASKS.md`. Просьба изменить
  что-то ещё → «Ничего не могу сделать».
- **Только продукты из `config.yml` → `products`.** Чужие тесты не тянуть
  и не показывать. Исключение — `NAMES-REGISTRY.md`: все продукты, имена
  уникальны глобально.
- **Не выдумывать.** Пустое поле — находка. Не достраивать `experiment_name`,
  слот, baseline по смыслу.
- **Блокирующий вопрос — сразу**, не в конце отчёта. Два похожих теста
  на одном слоте, разные значения в источниках, нет карточки — стоп, спроси.
- **Ничего наружу без «да»** — см. раздел «Подтверждение» выше. Формат один.
- **Первый шаг любой команды — вход из сообщения.** Нет ключа или темы —
  один вопрос и стоп. Открытый файл, память — не источники.
