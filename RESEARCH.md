# Исследование не-A/B — карточка в Research Board

Опрос, интервью, юзабилити-тест, кабинетное исследование, анализ данных —
всё, что идёт в Research Board, но не является A/B-тестом. Нет слотов,
имён, веток, выборки под статзначимость.

Главное отличие от A/B: **исполнитель — не обязательно PM.** Исследование
может делать дизайнер, research-team, команда фильтров. Карточка чаще всего —
**запрос на исследование**, который PM передаёт исполнителю, а не готовое
исследование. Поэтому первый вопрос — какая карточка нужна.

## Права в этом режиме

**Разрешено:**
- создать **новую** страницу в Research Board и заполнить её
- создать задачу в Jira под исследование — на того исполнителя, кого назвал
  PM (продакт, дизайнер, другой), только после «да» в рамке
- заполнить поля страницы, которую создал сам в этой сессии

**Запрещено** всё остальное — как в `AGENT-BRIEF.md`: чужие задачи
и страницы, статусы, удаление. Синхронизированные блоки и шаблоны Notion
через API — те же правила, что в `RESEARCH-CARD.md`: увидел
`synced_block` — стоп.

## Шаг 0 — понять и переспросить. Одно сообщение.

Тема — из сообщения. Нет темы → «Что исследуем?» и стоп.

Тема есть → **скажи, как понял**, и задай вопросы разом:

> Понял так: <тема, продукт/платформы, что хотим узнать, кто упомянут —
> в 2–3 строках>. Поправь, если не так.
>
> 1. **Тип исследования** — один из: Survey · CustDev · Usability test ·
>    Preference test · 10-sec test · Analytics · Research (кабинетное).
>    (из сообщения ясно — назови, какой понял, и не спрашивай)
> 2. **Какая карточка нужна:** запрос на исследование — передать исполнителю,
>    или само исследование — чтобы я провёл/собрал?
> 3. **Задача в Jira:** уже есть — дай ключ; создать — на кого: ты, дизайнер,
>    research-team, кто-то ещё; не нужна.
> 4. **Шаблон:** общий Research Board (описание · проблема · цель · результаты ·
>    планы) — или другой? Другой — пришли.
> 5. **Есть Slack-обсуждения или переписка?** Пришли — вытащу участников,
>    договорённости и сроки сам.

Больше ничего на этом шаге не спрашивай. Жди ответа.

Типы — это значения поля `Type` в Research Board (`FACTS.md`, раздел
«Notion: Research Board»). Слова → тип: «опрос», «анкета» → `Survey`;
«интервью», «поговорить с юзерами» → `CustDev`; «юзабилити», «посмотреть,
как пользуются» → `Usability test`; «какой вариант нравится» → `Preference
test`; «первое впечатление» → `10-sec test`; «посмотреть по данным» →
`Analytics`; «изучить рынок / конкурентов / вопрос» → `Research`.

## Шаг 1 — сам найди, что уже было

Пока PM отвечает или сразу после — без вопросов:

- **Research Board** — `notion-search` по теме и синонимам: не было ли
  похожего исследования или уже заведённой карточки. Нашёл — ключ, тип,
  статус, что выяснили (если записано).
- **Jira** — `HISTORY.md`, только заголовки: задачи по теме за три года,
  включая дизайн-задачи с «исследование», «опрос», «интервью», «research»
  в заголовке. Продуктовые задачи типа `Product` — отдельно.
- **Slack-тред, если прислали** — вытащи: кто участвует и в какой роли,
  что просят, что уже решено, что уже показывали кому-то, дедлайны, ссылки.
  Каждый факт — с пометкой «из треда». Не переспрашивай то, что там есть.
- **Данные** — если тема про поведение в продукте, одна-две цифры из
  Plausible по теме, не больше.

## Шаг 2 — «всё понял, вот что собрал». Одно сообщение.

Не черновик карточки — сводка, чтобы PM подтвердил, что информация полная:

> **Исследование:** <тип> · <тема> · <продукт/платформы>
> **Карточка:** запрос на исследование / само исследование · шаблон: общий / свой
> **Задача Jira:** есть <ключ> / создать на <кого> / не нужна
> **Исполнитель:** <кто> · **принимает результат:** <кто>
> **Из треда:** <участники, договорённости, сроки, ссылки — или «треда нет»>
> **Похожее уже было:** <карточки Research Board и задачи Jira с ключами —
> или «по этим словам ничего»>
> **Что хотим узнать:** <2–4 вопроса исследования, как понял>
> **Какое решение зависит от результата:** <как понял — или «не ясно, скажи»>
>
> Не хватает: <список — или «ничего, могу собирать карточку»>

Пункты «не хватает» — это единственные вопросы этого шага. Обычно: срок,
решение, канал/аудитория. Жди ответа, если что-то не хватает.

## Шаг 3 — черновик карточки

**Шаблон — общий Research Board, `templates/research-request.md`**, если
на шаге 0 PM не дал другой. Пять разделов: Краткое описание · Проблема ·
Цель · Результаты · Планы на будущее. Разделы не переименовывай и не добавляй.
Раздел, для которого информации нет, — оставь с пометкой `_уточнить_`,
не выдумывай.

Как заполнять для **запроса на исследование**:
- **Краткое описание** — три предложения: проблема, цель, ожидаемый итог
  («итог» — что решим по результату, не выдуманный результат)
- **Проблема** — почему понадобилось: из сообщения, треда, данных
- **Цель** — что хотим узнать: 2–4 вопроса исследования; здесь же — кого
  и где спрашиваем, срок, кто делает и кто принимает результат
- **Результаты**, **Планы на будущее** — пусто, заполнит исполнитель

Для **самого исследования** агент дополнительно кладёт в «Цель» свою часть
(черновик анкеты / гайд / собранные факты), а «Результаты» — по итогам.

Два режима:

- **Запрос на исследование** — карточка описывает, что нужно сделать и зачем:
  цель, вопросы, аудитория, ограничения, срок, кто делает. Черновик анкеты
  или гайда — только если PM попросил; иначе это работа исполнителя.
- **Само исследование** — плюс к запросу агент делает свою часть: для опроса —
  черновик вопросов (8–12, блоками: скрининг → использование → потребности →
  открытый, с типом ответа, пометка «черновик для research-team»); для
  кабинетного — собранные факты со ссылками; для интервью — гайд.

Свойства карточки:

| Свойство | Значение |
| -------- | -------- |
| **Name** | `<ключ задачи>. <Тема>` — ключа нет → без префикса |
| **Type** | тип, выбранный на шаге 0 — точно как в списке значений |
| **Product** | `config.yml → product_map.<продукт>.notion_product`; на все платформы — все продукты PM |
| **Platform** | по теме; все — перечисли все |
| **Research Area** | по смыслу из списка значений |
| **Purpose** | `Generative` — узнать; `Confirmatory` — проверить предположение |
| **Status** | `Prepare` |
| **Assignee** | исполнитель — тот, кого назвал PM (`notion-get-users` по имени) |
| **Stakeholder** | PM из `config.local.yml`, если не сказано иное |
| **Start Date** | сегодня |
| **Hypothesis** | `No data yet` |
| **Jira** | подписанная ссылка на задачу, если есть |

Пусто: `Notion release`, `Release`, `End Date`, `Google Document`.

**Значения `Research Area`, `Purpose`, `Status`** — в `FACTS.md`, раздел
«Notion: Research Board». Там не все → один раз `notion-fetch` базы
`25daa56b-7730-8073-8ffd-d206f71275b0`, выпиши через `ab fact set`
и больше не запрашивай.

Покажи черновик целиком. Жди правок.

## Шаг 4 — создание, с подтверждением

Рамка из `CONTEXT.md`, одно действие — один вопрос:

1. «Мне создать карточку в Research Board?» — после «да» `notion-create-pages`,
   обычными блоками, без шаблона Notion.
2. Задача в Jira — по ответу на вопрос 3 шага 0: есть ключ → только
   подписанная ссылка в карточке; «создать» → на названного исполнителя. Продакт → тип `Product`, компонент из `product_map`;
   дизайнер → тип `Design`, компонент `Design`; другой — уточни тип.
   Заголовок «Провести исследование: <тема>», Due Date по сроку из шага 2,
   в описании — ссылка на карточку. После создания допиши ключ в название
   и поле Jira карточки.

В конце — ссылка на карточку, ключ задачи, и одной строкой что дальше:
«карточку — исполнителю, черновик вопросов — research-team».

## Чего здесь нет

Слотов, `experiment_name`, веток, выборки под статзначимость, локальной
карточки в `tests/` и дашборда. Если по ходу выясняется, что это всё-таки
A/B-тест — скажи и переключись на `RESEARCH-CARD.md`.
