# Исследование не-A/B — карточка в Research Board

Опрос, интервью, юзабилити-тест, кабинетное исследование, анализ данных —
всё, что идёт в Research Board, но не является A/B-тестом. Сценарий
короче, чем `RESEARCH-CARD.md`: нет слотов, имён, веток, выборки под
статзначимость. Есть цель, решение, которое от неё зависит, вопросы,
аудитория, метод и люди.

## Права в этом режиме

**Разрешено:**
- создать **новую** страницу в Research Board и заполнить её
- создать продуктовую задачу в Jira «Провести исследование: <тема>» —
  только если PM попросил или подтвердил в рамке
- заполнить поля страницы, которую создал сам в этой сессии

**Запрещено** всё остальное — как в `AGENT-BRIEF.md`: чужие задачи
и страницы, статусы, удаление. Синхронизированные блоки и шаблоны Notion
через API — те же правила, что в `RESEARCH-CARD.md`: увидел
`synced_block` — стоп.

## Шаг 0 — тип и тема

Из сообщения. Тип — один из значений поля `Type` Research Board.
Список значений — в `FACTS.md`, раздел «Notion: Research Board», строка
`Type`. Там только `A/B` — один раз `notion-fetch` базы
`25daa56b-7730-8073-8ffd-d206f71275b0`, выпиши **все** значения `Type`,
`Research Area`, `Purpose`, `Status` через `ab fact set` и больше не запрашивай.

Слова → тип: «опрос», «анкета» → опрос; «интервью», «поговорить с юзерами»
→ интервью; «юзабилити», «посмотреть, как пользуются» → юзабилити;
«посмотреть рынок», «конкуренты», «изучить» → кабинетное. Точное имя —
из списка значений, не из головы.

Темы или типа нет → один вопрос и стоп.

## Шаг 1 — контекст до вопросов

Не спрашивай то, что можно узнать самому:

- **Что уже пробовали** — `HISTORY.md` по теме, только карта заголовков.
- **Продуктовая задача** — `jira_search_issues`: `project = AG AND issuetype
  = Product AND summary ~ "<тема>" AND created >= -180d`. Есть — возьми ключ.
- **Research Board** — `notion-search` по теме: не заведена ли карточка.
  Есть — покажи и спроси, дополнять или новую. Не дублируй.
- **Контекст из сообщения** — Slack-тред, письмо, скрин: вытащи всё, что
  там есть (кто участвует, что просят, дедлайн), и не переспрашивай.

## Шаг 2 — вопросы, одним сообщением

Только те, на которые нет ответа после шага 1. Обычно три-пять:

1. **Какое решение зависит от результата?** — если ответа нет, исследование
   не нужно; так и скажи.
2. **Что хотим узнать** — 2–4 вопроса исследования, не вопросы анкеты.
3. **Кого спрашиваем и где** — сегмент, платформы, канал (соцсети, in-app,
   рассылка, панель), сколько ответов хватит.
4. **Кто участвует** — research-team, дизайн, команда фильтров; кто
   принимает результат.
5. **Когда нужен результат.**

Не спрашивай про метод, если тип уже ясен из сообщения.

## Шаг 3 — черновик карточки

Тело — по `templates/research-generic.md`. Для опроса — предложи **черновик
вопросов анкеты**: 8–12, блоками «скрининг → использование → потребности →
открытый вопрос», каждый вопрос с типом ответа. Пометь «черновик для
research-team», не выдавай за готовую анкету. Не выдумывай данные
о пользователях и цифры — только то, что дал PM или есть в Plausible.

Свойства карточки:

| Свойство | Значение |
| -------- | -------- |
| **Name** | `<ключ продуктовой задачи>. <Тема>` — ключа нет → без префикса |
| **Type** | выбранный тип, точно из списка значений |
| **Product** | `config.yml → product_map.<продукт>.notion_product`; фича на все платформы — все продукты PM |
| **Platform** | по теме; все — перечисли все платформы продукта |
| **Research Area** | по смыслу из списка значений |
| **Purpose** | `Generative` — узнать; `Confirmatory` — проверить конкретное предположение |
| **Status** | `Prepare` |
| **Assignee**, **Stakeholder** | PM из `config.local.yml`; стейкхолдер другой — если PM назвал |
| **Start Date** | сегодня |
| **Hypothesis** | `No data yet` |
| **Jira** | подписанная ссылка на продуктовую задачу, если есть |

Пусто: `Notion release`, `Release`, `End Date`, `Google Document`.

Покажи черновик целиком. Жди правок.

## Шаг 4 — создание, с подтверждением

Рамка из `CONTEXT.md`, одно действие — один вопрос:

1. «Мне создать карточку в Research Board?» — после «да» `notion-create-pages`,
   обычными блоками, без шаблона Notion.
2. Если продуктовой задачи нет и PM хочет: «Мне создать продуктовую задачу
   „Провести исследование: <тема>“?» — тип Product, компонент из
   `product_map`, assignee PM, Due Date +5 дней, в описании — ссылка на карточку.
   После создания допиши ключ в название и поле Jira карточки.

В конце — ссылка на карточку, ключ задачи, и одной строкой что дальше:
«черновик вопросов — research-team, канал — …».

## Чего здесь нет

Слотов, `experiment_name`, веток, выборки под статзначимость, локальной
карточки в `tests/` и дашборда. Если по ходу выясняется, что это всё-таки
A/B-тест — скажи и переключись на `RESEARCH-CARD.md`.
