# Режим: заведение задач по тесту

Расширяет `AGENT-BRIEF.md` **только для одной задачи** — создания комплекта
Jira-задач по готовой карточке эксперимента. Во всём остальном действует бриф.

Именование — строго по `NAMING.md`.

---

## Права в этом режиме

**Разрешено:**
- создавать **новые** задачи в Jira
- проставлять связи между задачами, которые создал сам
- дописать блок «Параметры эксперимента» в dev-задачу, которую создал сам
  (это единственное разрешённое редактирование — см. «Курица и яйцо»)
- обновить карточку Notion, к которой относятся задачи

**По-прежнему запрещено:**
- менять чужие задачи: описание, статус, исполнителя, версии
- переводить задачи по workflow
- комментировать чужие задачи и PR
- удалять что-либо

На просьбу сделать запрещённое — ответ прежний: «Ничего не могу сделать».

**Создание — только после «да».** Вопрос в рамке по формату из `CONTEXT.md`:
«Мне создать эти N задач?» + черновики списком. Стоп до ответа.
Обновление карточки Notion после создания — отдельный вопрос:
«Мне дописать ссылки в карточку?»

---

## Справочник FACTS.md — читай до того, как звать метаданные

Перед любым `jira_create_issue` открой `FACTS.md`. Если нужный
проект и тип там описаны — используй поля оттуда и **не вызывай**
`Get Tool Schema` и `jira_get_create_meta`. Если нет — вызови один раз
и допиши результат в справочник, чтобы в следующий раз не спрашивать.

## Что создаём

Четыре задачи на старте. Шаблоны — в `templates/`, бери описания оттуда.

| Задача | Шаблон | Проект | Тип |
|---|---|---|---|
| Дизайн | `jira-design-task.md` | AG | Design |
| Разработка | `jira-dev-task.md` | AG | Задача |
| Бэк: регистрация эксперимента | `jira-backend-task.md` | ADG | Задача |
| Выпиливание из клиента | `jira-cleanup-task.md` | AG | Задача |

Шестая задача — **закрытие теста на бэке** (`jira-backend-close-task.md`, проект ADG) —
заводится не сейчас, а когда принято решение по тесту: в ней указывается победившая
ветка. При создании комплекта её не создавай, но упомяни в отчёте, что она понадобится
на шаге 9.

Проекты и типы указаны по прошлым тестам (AG-57632, AG-50080, ADG-12912).
**Перед созданием проверь через `jira_get_create_meta`**, какие поля обязательны
в этих проектах, и покажи в черновике, что именно будешь заполнять.

Во всех задачах:
- **Assignee — PM из `config.yml`** (`pm.name`, `pm.jira_username`)
- метка `Split-Testing`
- у задачи на выпиливание дополнительно метка `cleanup`

Версию (Fix Version) и спринт **не проставляй** — это ставится руками.

Приоритет: в бэк-задачах ADG ставь `P2: High` (так заведено в ADG-12912, ADG-12617).
В остальных задачах приоритет не трогай.

**Due date** — обязательное поле в проекте ADG. По прошлым задачам срок ставится
примерно через неделю от создания: бэк-задача блокирует разработку, поэтому
должна быть закрыта до её старта. Точную дату спрашивай.


### Пятая задача — на закрытие теста на бэке

`templates/jira-backend-close-task.md`, проект ADG, компонент BackendJava.

**В стартовый комплект она не входит.** Заводится на шаге 9, когда известен
победитель: в ней указывается победившая ветка, которую надо назначить fallback.
Заранее её создать нельзя — нечего писать.

Если пользователь просит завести задачи по тесту, у которого уже есть решение,
эту задачу создавай тоже. В остальных случаях — не создавай, а напомни,
что она понадобится после анализа.

## Порядок создания

`experiment_name` уже есть в карточке — он собран из ключа продуктовой
задачи на этапе подготовки. **Бери его оттуда дословно, не генерируй.**
Если в карточке имени нет — это ошибка подготовки: остановись и скажи,
задачи из такой карточки создавать нельзя.

Порядок:

1. **Дизайн-задача** — ни от чего не зависит
2. **Dev-задача** — создаётся с пустым блоком параметров, получаем ключ `AG-XXXXX`
   В описании — блок «Телеметрия»: события, `experiment_*` в событиях,
   проверка в Plausible. Это часть задачи, не отдельная сущность.
3. **Собери `experiment_name`** = `AG-XXXXX` + slug по правилам `NAMING.md`
4. **Бэк-задача** — «Add information about Test AG-XXXXX to the service»,
   уже с готовым `experiment_name` и списком версий `-a_def` / `-b`
4. **Задача на выпиливание** — ссылается на dev

Курицы и яйца больше нет: имя известно до первой задачи.

## Связи между задачами

| Задача | Связь |
|---|---|
| Dev | *is blocked by* дизайн |
| Dev | *is blocked by* бэк |
| Dev | *relates to* выпиливание |

## Проверка на дубли — до всего остального

Прежде чем что-то создавать, найди, не заведены ли задачи по этому тесту:

```
jira_search_issues, jql:
  (summary ~ "<название теста>" OR text ~ "<slug>")
  AND created >= -90d
  ORDER BY created DESC
```

Если что-то похожее нашлось — покажи мне и спроси, прежде чем продолжать.
Восемь задач вместо четырёх чистить руками, ты этого сделать не сможешь.

## Обновление карточки Notion

После создания задач допиши в карточку:

1. **Название**: добавь префикс — `AG-XXXXX. <прежнее название>`, ключ dev-задачи
2. **Поле Jira**: подписанные ссылки на все четыре задачи —
   `дизайн задача`, `разработческая задача на имплементацию`,
   `бэк задача на регистрацию эксперимента`, `задача на выпиливание`
3. **В тело карточки**, в раздел «Дизайн эксперимента» — блок с параметрами:

```
experiment_name: AG-XXXXX-<slug>
Слот: experiment_N
Контроль: AG-XXXXX-<slug>-a_def
Вариант B: AG-XXXXX-<slug>-b
```

Эти значения должны дословно совпадать с тем, что в задачах. Сверь символ
в символ перед тем, как записывать.

## Отчёт

После создания напиши:

- какие задачи созданы, с ключами и ссылками
- какие связи проставлены
- что записано в карточку
- **что осталось за мной**: версии, приоритеты, спринт, согласование с аналитиком

Если что-то упало посередине — скажи, что успел создать, а что нет.
Не пытайся откатить: удалять ты не можешь.
